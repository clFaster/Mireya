# API

Mireya exposes REST endpoints for admin operations and screen clients, plus a SignalR hub for live screen communication.

## Authentication model

Mireya uses ASP.NET Identity.

Roles:

- `Admin`: administrators using the web UI and protected management APIs.
- `Screen`: approved display clients.

Browser-facing admin pages use cookie authentication. API clients and display clients use bearer tokens. SignalR screen connections pass the bearer token as an `access_token` query parameter during the WebSocket upgrade; the API copies it into the authorization header before authentication runs.

## Public and operational endpoints

| Endpoint | Auth | Purpose |
| --- | --- | --- |
| `GET /api/info` | Public | Returns server identity, including application name and version. |
| `GET /alive` | Public/service-defaults | Liveness probe. |
| `GET /health` | Public/service-defaults | Readiness probe including database connectivity. |

In Development, OpenAPI and Swagger UI are enabled through NSwag.

## Admin endpoint groups

These groups require the `Admin` role unless noted.

### Assets: `/api/assets`

| Endpoint | Purpose |
| --- | --- |
| `POST /api/assets/upload` | Upload one or more media files. |
| `GET /api/assets/` | List assets with paging/filtering parameters. |
| `DELETE /api/assets/{id}` | Delete an asset. |
| `PUT /api/assets/{id}/metadata` | Update asset metadata such as name, description, tags, image fit, duration, or mute state. |
| `POST /api/assets/website` | Create a website URL asset. |

### Campaigns: `/api/campaign`

| Endpoint | Purpose |
| --- | --- |
| `GET /api/campaign/` | List campaigns. |
| `GET /api/campaign/{id}` | Get campaign details. |
| `POST /api/campaign/` | Create a campaign. |
| `PUT /api/campaign/{id}` | Update campaign details and playlist content. |
| `DELETE /api/campaign/{id}` | Delete a campaign. |
| `GET /api/campaign/fallback` | Get the scheduled global-fallback assignment. |
| `PUT /api/campaign/fallback` | Create or replace the scheduled global-fallback assignment. |
| `DELETE /api/campaign/fallback` | Remove the global-fallback assignment. |

### Screen management: `/api/screenmanagement`

| Endpoint | Auth | Purpose |
| --- | --- | --- |
| `POST /api/screenmanagement/register` | Public | Register a display client and return registration data. |
| `GET /api/screenmanagement/bonjour` | `Screen` | Let an authenticated screen fetch its current screen identity/status. |
| `GET /api/screenmanagement/` | `Admin` | List screens. |
| `GET /api/screenmanagement/{id}` | `Admin` | Get screen details. |
| `PUT /api/screenmanagement/{id}` | `Admin` | Update screen metadata and playback settings. |
| `GET /api/screenmanagement/{id}/campaign-assignments` | `Admin` | Get this screen's campaign assignments and schedules. |
| `PUT /api/screenmanagement/{id}/campaign-assignments` | `Admin` | Replace this screen's assignments and per-assignment schedules. |
| `POST /api/screenmanagement/{id}/approve` | `Admin` | Approve a pending screen and provision screen access. |
| `POST /api/screenmanagement/{id}/reject` | `Admin` | Reject a pending screen. |
| `POST /api/screenmanagement/{id}/command` | `Admin` | Send a remote command to a connected screen. |
| `GET /api/screenmanagement/online/count` | `Admin` | Return the count of online screens. |

### Asset sync: `/api/assetsync`

| Endpoint | Auth | Purpose |
| --- | --- | --- |
| `POST /api/assetsync/status` | `Screen` | Update sync state and progress for an asset. |
| `GET /api/assetsync/status` | `Screen` | Get sync status for the current screen. |
| `GET /api/assetsync/campaigns` | `Screen` | Get assigned and fallback campaign assets to pre-cache for the current screen. |
| `GET /api/assetsync/{displayId}/status` | `Admin` | Get sync status for a specific display. |

### Audit: `/api/audit`

| Endpoint | Purpose |
| --- | --- |
| `GET /api/audit/` | List audit entries. |

## Authentication endpoints

The app maps the built-in ASP.NET Identity API endpoints, plus admin-cookie helpers:

| Endpoint | Purpose |
| --- | --- |
| `POST /auth/login` | Sign in to the admin UI with cookies. |
| `POST /auth/logout` | Sign out of the admin UI. |
| `POST /account/logout` | Authenticated account logout endpoint. |

Identity also exposes standard register/login/refresh/manage endpoints generated by `MapIdentityApi<User>()`. Client code should use the generated NSwag client rather than hard-coding those routes.

## SignalR screen hub

Screens connect to:

```text
/hubs/screen
```

Hub behavior:

- Server sends configuration updates with active screen campaigns.
- Server sends asset-sync requests when campaigns should be downloaded.
- Admin remote commands are pushed as command identifiers.
- Clients report the currently playing asset for now-playing/proof-of-play tracking.
- Clients reconnect automatically and refresh state after reconnect.

Supported remote command identifiers:

- `restart`
- `reload`
- `identify`
- `next`
- `previous`

## Screen registration and sync flow

1. Client probes a backend with `/api/info`.
2. Client registers with `/api/screenmanagement/register`.
3. Admin approves the pending screen.
4. Client authenticates as a screen.
5. Client calls `/api/screenmanagement/bonjour` to read screen status.
6. Client connects to `/hubs/screen`.
7. Server sends configuration and asset-sync messages.
8. Client downloads required image/video assets and reports progress to `/api/assetsync/status`.
9. Client plays the playlist and reports now-playing events over SignalR.

## Generated API client

`src/Mireya.ApiClient` contains:

- `Generated/MireyaApiClient.cs`: NSwag-generated REST client and DTOs.
- API client configuration services.
- Authentication and credential-management services.
- Backend selection/management.
- SignalR hub service.
- Local asset sync service.
- Client-side SQLite context and migrations.

Regenerate the client after API contract changes:

```bash
dotnet tool restore
cd src/Mireya.ApiClient
dotnet nswag run nswag.json
```

The NSwag configuration builds the API project in Development mode and writes to `Generated/MireyaApiClient.cs`.
